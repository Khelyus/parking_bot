# План дообучения модели на реальных кадрах

Ниже описан практический план дообучения модели именно под текущий проект `parking_bot`.

Рекомендуемый порядок такой:

1. Сначала улучшить `slot classifier` на реальных кропах парковочных слотов.
2. Только потом, если останутся системные ошибки, дообучать full-frame YOLO.

Это даёт лучший результат при меньших затратах времени.

## Цель

Добиться устойчивого определения `empty/occupied` на реальных фиксированных камерах:

- в разное время суток
- при разной погоде
- при бликах, тенях и пересвете
- при частичном перекрытии машин

## Этап 0. Зафиксировать baseline

Перед любым дообучением нужно зафиксировать текущий уровень качества.

1. Выбрать 3-5 самых важных камер.
2. Для каждой камеры собрать маленький тестовый набор:
   - 30-50 кадров на камеру
   - день, вечер, ночь
   - разная погода
   - разная заполненность парковки
3. Сохранить их в отдельную папку, например:

```text
runtime/eval_baseline/<camera_id>/
```

4. Для этих кадров вручную зафиксировать ground truth:
   - либо по слотам `empty/occupied`
   - либо хотя бы итоговое состояние камеры
5. Прогнать текущую модель и отдельно отметить ошибки:
   - ложные `empty`
   - ложные `occupied`
   - пропуски
   - ошибки ночью, в бликах, в снегу, в тенях

Этот набор нужен, чтобы потом честно сравнить старую и новую модель.

## Этап 1. Подготовить камеры к обучению

Если у камер ещё нет корректно описанных `parking_slots`, сначала нужно привести конфиг в порядок.

1. Для каждой камеры задать список `parking_slots` в `config/cameras.yaml`.
2. Проверить, что слоты:
   - накрывают именно парковочные места
   - не захватывают лишнюю дорогу
   - не захватывают посторонние зоны
3. Если есть шумные области, задать `detection_exclude_rois`.
4. Если кадр слишком широкий, задать `detection_roi`.

Если слоты размечены неточно, дальнейшее дообучение будет ограничено качеством этой разметки.

## Этап 2. Накопить реальные кадры

Нужен не один набор скриншотов, а полноценная выборка.

Минимально полезный объём:

- 500-1000 кадров на камеру

Лучше:

- 2000+ кадров на камеру

Что обязательно покрыть:

- утро
- день
- вечер
- ночь
- сухая погода
- дождь
- снег и грязь
- пустая парковка
- почти полная парковка
- тени
- блики
- сложные спорные сцены

Рекомендуемая структура хранения:

```text
runtime/training_frames/<camera_id>/2026-05-06_08-15-00.jpg
runtime/training_frames/<camera_id>/2026-05-06_08-20-00.jpg
runtime/training_frames/<camera_id>/2026-05-06_08-25-00.jpg
```

Лучше сохранять архив кадров с timestamp, а не только один текущий `*_raw.jpg`.

## Этап 3. Отобрать полезные кадры

Не нужно размечать всё подряд.

Нужно убрать:

- почти одинаковые соседние кадры
- битые изображения
- дубли
- кадры, где парковка почти не видна

Нужно оставить:

- разнообразные сцены
- трудные случаи
- реальные типовые ошибки модели
- редкие условия, которые важны для эксплуатации

Лучше меньше, но разнообразнее.

## Этап 4. Автоматически построить псевдоразмеченный датасет слотов

В проекте для этого уже есть скрипт:

- `scripts/build_slot_calibration_dataset.py`

Он:

- читает камеры и слоты
- прогоняет текущий pipeline
- использует classifier и vehicle detector
- отбирает уверенные `space-empty` и `space-occupied`
- экспортирует кропы слотов в датасет

Базовый запуск:

```bash
python scripts/build_slot_calibration_dataset.py --project-root . --output-dir runtime/slot_calibration_dataset
```

Если нужно обработать только часть камер:

```bash
python scripts/build_slot_calibration_dataset.py --project-root . --output-dir runtime/slot_calibration_dataset --cameras cam1 cam2 cam3
```

Смысл этого этапа:

- модель сама делает черновую разметку
- человеку не нужно рисовать боксы вручную
- остаётся только быстро проверить и почистить результат

## Этап 5. Ручная чистка псевдоразметки

После экспорта получится структура примерно такого вида:

```text
runtime/slot_calibration_dataset/space-empty/
runtime/slot_calibration_dataset/space-occupied/
runtime/slot_calibration_dataset/metadata.json
```

Что делать:

1. Быстро просмотреть `space-empty`.
2. Все ошибочные примеры перенести в `space-occupied` или удалить.
3. Затем просмотреть `space-occupied`.
4. Все ошибочные примеры перенести в `space-empty` или удалить.

Правила чистки:

- сначала убрать грубый шум
- сомнительные кропы лучше удалить
- лучше меньше, но чище
- особенно внимательно чистить ночные, бликовые и теневые кадры

Ориентир по размеру:

- 2000-5000 чистых кропов на класс уже полезно
- 5000-15000 на класс обычно даёт хороший результат

## Этап 6. Дообучить slot classifier

В проекте для этого есть:

- `scripts/fine_tune_slot_classifier.py`

Базовый запуск на CPU:

```bash
python scripts/fine_tune_slot_classifier.py \
  --dataset-dir runtime/slot_calibration_dataset \
  --base-model models/pklot_slot_classifier.pt \
  --output models/pklot_slot_classifier.pt \
  --epochs 12 \
  --batch 16 \
  --learning-rate 0.00015 \
  --device cpu
```

Если есть GPU:

```bash
python scripts/fine_tune_slot_classifier.py \
  --dataset-dir runtime/slot_calibration_dataset \
  --base-model models/pklot_slot_classifier.pt \
  --output models/pklot_slot_classifier.pt \
  --epochs 12 \
  --batch 32 \
  --learning-rate 0.00015 \
  --device 0
```

На что смотреть:

- `val_acc`
- не уходит ли train сильно вверх при просадке val
- не переобучилась ли модель на одну камеру

Если данных мало:

- уменьшить `epochs`
- сильнее чистить шум
- добавить больше кадров

## Этап 7. Проверка на baseline-наборе

После fine-tune нужно сравнить новую модель со старой на baseline-наборе из этапа 0.

Проверять:

- стало ли меньше ложных свободных мест
- стало ли меньше ложных занятых мест
- как ведёт себя модель ночью
- как ведёт себя модель в бликах и тенях
- не ухудшились ли простые дневные случаи

Если модель стала лучше только на одной камере, а на остальных хуже, значит датасет был слишком узким.

## Этап 8. Повторить цикл pseudo-label -> clean -> fine-tune

Обычно одной итерации недостаточно.

Рекомендуемый цикл:

1. Дообучить classifier.
2. Снова прогнать pseudo-labeling на новых кадрах.
3. Снова быстро почистить датасет.
4. Снова сделать fine-tune.

2-3 таких итерации часто дают лучший результат, чем один большой прогон.

## Этап 9. При необходимости дообучить full-frame YOLO

Это второй этап, а не первый.

Он нужен, если:

- ошибки возникают ещё до классификации слота
- модель плохо находит сами parking-space области
- slot pipeline недостаточен
- хочется улучшить full-frame детекцию целиком

Для этого понадобится отдельный full-frame датасет.

Пайплайн:

1. Собрать реальные полные кадры.
2. Авторазметить их текущей моделью.
3. Исправить боксы вручную в CVAT, Roboflow или Label Studio.
4. Подготовить `data.yaml`.
5. Запустить обучение через:

```bash
python scripts/train_model.py --data path/to/data.yaml --model yolov8n.pt --epochs 50 --imgsz 640 --batch 16 --device 0
```

Но этот путь дороже по времени, чем fine-tune slot classifier.

## Как автоматизировать подготовку датасета другой нейронкой

Да, можно. И в текущем проекте это уже частично реализовано.

Лучший вариант для этого проекта:

- использовать уже существующий pipeline как авторазметчик
- затем вручную чистить только результат

Что уже есть:

- classifier оценивает слот
- vehicle detector подтверждает `occupied`
- экспортируются только достаточно уверенные примеры

То есть основной механизм pseudo-labeling уже встроен.

Дополнительно полезно автоматизировать:

- сохранение кадров по расписанию
- отбор только новых или разнообразных кадров
- отдельную папку для low-confidence примеров
- повторную авторазметку после каждой новой версии модели

Наиболее рабочая схема:

1. Модель размечает основную массу примеров.
2. Человек быстро чистит результат.
3. Модель дообучается.
4. Цикл повторяется.

## Как удобно и быстро размечать вручную

### Для slot classifier

Это самый быстрый и удобный вариант.

Преимущества:

- не нужно рисовать боксы по всему кадру
- нужно только проверять готовые кропы слотов
- задача сводится к бинарной сортировке `empty/occupied`

Практически удобно:

- вручную править папки `space-empty` и `space-occupied`
- использовать Label Studio как image classification tool
- при желании написать маленький review-tool с горячими клавишами

### Для full-frame YOLO

Лучшие варианты:

- CVAT
- Roboflow
- Label Studio с разметкой bbox

Наиболее быстрый путь:

1. Авторазметка текущей моделью.
2. Ручная правка только ошибок.
3. Retrain.
4. Повторная авторазметка уже новой моделью.

## Рекомендуемые объёмы данных

### Для slot classifier

- минимально полезно: 1000-2000 кропов на класс
- хороший рабочий объём: 5000-10000 кропов на класс
- очень хороший: 10000+ на класс

### Для full-frame YOLO

- минимально полезно: 300-500 размеченных кадров
- нормальный старт: 1000-3000 кадров

Ключевое здесь не только количество, но и разнообразие.

## Типичные ошибки, которых нужно избегать

- обучать только на дневных кадрах
- собирать датасет только с одной камеры и ждать качества на всех
- оставлять много шумной псевдоразметки
- переучивать модель на слишком узкий набор
- не держать отдельный baseline-набор
- смешивать training и evaluation в одной папке

## Практический цикл работ

Рекомендуемая последовательность:

1. Настроить `parking_slots` и сбор кадров.
2. Накопить архив реальных кадров.
3. Собрать baseline-набор.
4. Экспортировать pseudo-labeled dataset.
5. Очистить датасет вручную.
6. Выполнить fine-tune classifier.
7. Проверить качество на baseline.
8. Повторить цикл ещё 1-2 раза.
9. Только потом решать, нужен ли retrain full-frame YOLO.

## Что делать прямо сейчас

Самый полезный стартовый план:

1. Выбрать 3-5 камер.
2. Собрать по ним реальные кадры.
3. Проверить корректность `parking_slots`.
4. Запустить:

```bash
python scripts/build_slot_calibration_dataset.py --project-root . --output-dir runtime/slot_calibration_dataset
```

5. Почистить `space-empty` и `space-occupied`.
6. Запустить:

```bash
python scripts/fine_tune_slot_classifier.py --dataset-dir runtime/slot_calibration_dataset --base-model models/pklot_slot_classifier.pt --output models/pklot_slot_classifier.pt --epochs 12 --batch 16 --device cpu
```

## Краткий вывод

Для текущего проекта наиболее эффективный путь такой:

1. Не начинать сразу с полного переобучения YOLO.
2. Сначала использовать фиксированные `parking_slots`.
3. Автоматически собрать псевдоразмеченные кропы слотов.
4. Быстро почистить их вручную.
5. Дообучить `slot classifier`.
6. Оценить результат.
7. И только если этого недостаточно, идти в full-frame retrain YOLO.
